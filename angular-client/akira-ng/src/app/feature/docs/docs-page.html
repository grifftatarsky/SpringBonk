The gist

You make shelves. You put books on shelves. You start an election. People nominate candidates (usually from shelves). Everybody ranks the candidates. Akira runs an instant-runoff and tells you who won. That's it.

Architecture

One request, front to back — plus a second UI the shell pulls in at runtime.

Browser
Angular 22 shell (SPA)
Oozengine UI pulled in at runtime via Native Federation
NGINX
reverse proxy · serves the SPA + /remotes/ooze
BFF
Spring Cloud Gateway · session · token relay
↔
Keycloak
OAuth 2 / OIDC
routed by path — /api + /ooz
Resource server
Akira · Spring Boot · JWT · JPA
Oozengine
DM tools · Spring Boot · JWT · JPA
PostgreSQL
akira-db · ooz-db · Liquibase

The BFF keeps the session and relays a token inward, so both backends only ever see a signed JWT — never a password or a cookie. Akira's library/election API and Oozengine's DM-tools API are independent Spring Boot services with their own Postgres databases; NGINX hands /api to one and /ooz to the other.

Oozengine's interface is its own Angular build, not bundled into Akira. The shell loads it on demand with Angular Native Federation — so the DM tools ship on their own cadence, and if Oozengine is offline the rest of Akira doesn't notice.
